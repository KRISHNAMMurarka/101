## Reproduced failures and review

- Driver, manual parser, provider and game bridge missing-module regressions failed before implementation. Driver tests cover original capture retention, relative state recovery, no anchor, resize, competing touches, rate/heartbeat, reliable contact and terminal release under failed/backward/reentrant clocks and callbacks.
- A surface grant created at construction expired during a 70-second manual transfer before owner consent. The smallest test failed before moving grant creation to explicit selection. Approval still lasts one minute and is not automatically extended.
- Counting two active bindings incorrectly allowed an unrelated capability to substitute for Contact. The regression failed before the capability-specific `isBound()` check; provider input requires both actual Position and Contact routes.
- Independent review reproduced same-turn native sends exceeding the raw byte limit because installed native JS posts sends without synchronously updating `bufferedAmount`. The adapter now reserves bytes before bridge submission and caps pending commands at 256, including empty payloads. Only exact owned cumulative native sent statistics credit reservations. A malformed bytes/count prefix reproduced a 257th admission before bounded per-message byte endpoints made credit coherent. Stats prove SCTP handoff, not remote receipt or effect.
- Actual iOS simulator offer creation failed. Installed iOS delivery getters are uint16 and expose unset as 65535, unlike Android's -1. A faithful producer fixture reproduced incompatible delivery. Explicit host sentinel selection now normalizes65535 only for locally initiated omitted options; explicit finite 65535 and incoming65535 remain unqualified. Focused 20/20 adapter tests and independent review pass, and actual native offer/data-channel operation succeeds. Android incoming-channel metadata still cannot qualify disposable delivery; native sources deliberately initiate both channels.
- Game bridge malformed extra vector fields and undeclared manifest input sources failed before strict schema/source validation. Eleven bridge tests and independent caller review pass. The owner supplies `mapping.source`; packet/platform labels cannot choose or imply physical input.
- Native virtual drags produced begin/end Contact but no Position movement. A temporary scroll/responder ownership experiment did not change that observation and was reverted. Source logic versus simulator automation has not been isolated; touch movement remains unqualified. Direction controls and accessible contact actions reach the browser, and Stop/background retirement releases output. No virtual gesture is recorded as physical touch acceptance.

Independent final adapter and game consumer reviews report no remaining actionable Important/Critical source findings in their bounded scope. The unresolved native gesture and failed WebKit UI are qualification failures preserved above.

## 5 October 2026 physical Android update

A OnePlus IV2201 running Android 13 sent ADB-injected touch input through the native pointer lab and its native WebRTC provider to the browser `/pointer-lab` application sink. The browser used a fresh local production build (`6a1e9cc508104f9d`); the installed native Release APK SHA256 was `94e286dd0abe169bea79a8ab25f27ff86a4f6eb044aaa0f9aeee1634a1065fa4`. Node was 24.14.0 and Playwright was 1.61.1. The source and sink exchanged complete offers/answers, compared the same full endpoint code, each approved the connection, and the browser owner allowed pointer control for one minute. The receiving surface is a general application pointer, not a 101 game role.

With the original native responder setting, two ADB diagonal swipes moved the rendered browser marker from `(455, 198.5)` to `(496.282, 214.009)` and then `(391.731, 200.442)` CSS pixels. Browser contact changed `false → true → false → true → false`; the route remained active. The pad's screen bounds changed during the swipes because the native page scrolled; the second swipe used its newly measured bounds. A separate experiment with responder termination denied also moved both diagonals and still scrolled the page, so that native change was reverted. This observation closes generic native-to-browser binding (T07); it does not prove human finger interaction, the iPhone, resize/no-anchor or physical capture-to-render latency requirements of T08.

A later Android Release candidate (`69836113ec8b6b32ef13c485065af0bbb16e6f00437ae8fc40a1934c75874c86` SHA256) disables the enclosing ScrollView only while a ready pad touch is active and restores it on lift, cancellation, stop or responder termination. The earlier physical run provided the failing baseline: the pad bounds changed during a swipe. With the new candidate and the same local browser sink, the pad stayed at `[72,1539][1008,2161]` through both ADB diagonals. The marker moved `(455,198.5) → (910,397) → (326.218,186.163)` CSS pixels, contact again changed `false → true → false → true → false`, and the browser permission remained active. After release, a swipe outside the pad scrolled the native page, verifying recovery. This resolves the observed Android pad-scroll conflict. It remains partial T08 evidence because human finger interaction, iPhone pairing, resize/no-anchor and physical capture-to-render latency have not passed.

The first Android pairing with the prior receiver code stopped while both peers were approved: a valid position packet arrived 103.3 ms after the previous packet against `maxAgeMs=100`. A regression failed on the old code at 150 ms silence. The receiver now uses a bounded 500 ms minimum route-silence timeout while each packet still must satisfy its original 100 ms freshness limit; immediate disconnect/stop and one-minute owner-grant expiry still release output. The regression passes with a fresh packet after the brief gap and verifies release after 501 ms silence. This is a liveness fix, not a relaxation of stale packet admission. The physical swipes above passed with that fix and the unchanged native responder setting.
