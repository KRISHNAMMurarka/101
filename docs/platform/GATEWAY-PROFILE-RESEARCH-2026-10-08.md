# A15 permitted first gateway profiles — research

Research observed 8 October 2026. Repository context: `337cdce4c62b6dae075a937194a11741c6bfeb99`. This record describes proposed first profiles and future qualification gates. It adds no implementation, dependency, installed native component, support row, or physical receipt. Profile identifiers below are research identifiers, not published SDK schemas.

## Acceptance and existing boundaries

`MASTER-CHECKLIST.md` A15 explicitly asks to research and record permitted first profiles before implementation or support claims. A16 separately requires heterogeneous measurements through a real gateway. Thus A15's research deliverable can be completed locally with documented access constraints; it cannot close A16 or create a qualified device combination. The A-group introduction, Q03/Q08 and qualification envelope still require faithful fixtures and physical receipts before connector support is promoted. The generic “Selected physical protocol gateway and target firmware” equipment entry attached to pending-A15 does not supply evidence or override the specific research scope.

The task dependency record names M01/T01/S01 as planning minima, explicitly not a complete dependency graph. A future implementation must also name its actual dependencies: A01 profile manifest work, selected native host lifecycle and privilege boundary (N12/N15/S12 as applicable), ownership/route authority, Q03 faithful fixtures, Q02 installed public caller, and Q08 physical qualification. Reusing selected A05 MQTT software does not close its broad device acceptance. No currently selected software implementation implies these new profiles work.

The design and release contract separate discovery, enrollment, permission, resource authority and evidence. Physical devices with no cryptographic identity are gateway-owned observations with that limitation. Names, chip IDs, USB serials, GPIO labels, BACnet device instances and DevEUIs are selection hints, not grants. Every future profile must freeze the source host identity, driver/library/build, resource selector, decoder/version, native settings, typed schema and limits. Approval must precede native acquisition/network dispatch and bind the exact immutable request; runtime routes retain their original recipient, principal, operation, expiry and generation.

Reuse candidates already exist in `packages/device-model/src/descriptor.ts` (bounded scalar, enum, boolean, record, arrays of at most 128 members), `packages/device-runtime/src` (route and verified resource ownership), and `packages/hub-server/src/gateway-inventory.ts` (scoped enrolled gateway inventory). Arbitrary protocol text and UTC strings belong to truthful provenance until an explicitly supported public schema exists. Byte capture should use bounded verified resources or a deliberately bounded numeric array profile; it must not silently expand M01 limits or invent a live binary codec.

## First profiles

### GPIO: `linux-gpio-v2-single-input-edge/1`

Select one Linux GPIO chip by enrolled stable sysfs/device identity plus one line offset; record chip name/label as hints. The native boundary is character-device API v2, introduced in Linux 5.10, with `GPIO_V2_GET_LINE_IOCTL` requesting one INPUT line and explicit rising/falling flags. Publish logical active/inactive edges, offset, request sequence and line sequence; keep nanosecond native `CLOCK_MONOTONIC` time in its actual clock domain. ACTIVE_LOW inverts physical polarity, so it must be part of enrollment. A sequence discontinuity means loss, not a manufactured transition. Kernel buffer sizing is advisory and overflow discards old events. [Kernel API](https://docs.kernel.org/userspace-api/gpio/chardev.html), [event read semantics](https://docs.kernel.org/userspace-api/gpio/gpio-v2-line-event-read.html).

Permit input acquisition and observation only. No output drive, pull/bias change, PWM, bit-banged I²C/SPI or reconfiguration after opening. Board wiring, voltage compatibility, line use and permission on the device node must be approved separately. Release closes the owned request; reopen gets a new epoch and does not replay buffered old events. First software check: faithful native-event fixtures for logical polarity, sequence loss, duplicate/stale epoch, bounded reads, cancellation and release. First equipment check: one named Linux board/kernel, documented unused input line and safely connected switch or signal source, including denied/busy line, unplug/loss and measured release. Unsupported v2, busy line or denied access remains unavailable.

### I²C: `linux-tmp102-hwmon-temperature-read/1`

Select an already provisioned TI TMP102 through its enrolled Linux I²C parent path/address and `tmp102` hwmon identity; read only `temp1_input`. Use the existing kernel driver rather than a new raw bus adapter. Freeze kernel/driver build and actual conversion interval. The selected source is fixed-point millidegrees Celsius; a declared exact conversion can produce `Cel`, preserving the original integer and conversion provenance. No temperature limits or update-interval writes are exposed. [TMP102 driver](https://docs.kernel.org/hwmon/tmp102.html), [hwmon ABI](https://github.com/torvalds/linux/blob/master/Documentation/ABI/testing/sysfs-class-hwmon).

The underlying TMP102 register uses signed temperature coding with 0.0625°C resolution; extended mode changes the register layout. The selected producer is the kernel's temperature ABI, not arbitrary two-byte I²C data. The vendor reference is SBOS397I, revised June 2024. Native-driver setup/configuration is host provisioning and must be recorded; it is not claimed to perform no bus writes. A future raw alternative would need enrolled mode/address and a pointer-select/read transaction, checked `I2C_FUNC_I2C`/`I2C_RDWR`; it is outside this first profile. [TI datasheet](https://www.ti.com/lit/ds/symlink/tmp102.pdf), [Linux I²C transactions](https://docs.kernel.org/i2c/dev-interface.html).

First software check: actual ABI text fixtures with negative values, exact decimal conversion, truncated/noninteger/overflow text, missing file, read error, startup conversion availability, stale value and changed parent identity. Repeated polling is receiver observation, not proof of a new sensor conversion. Equipment: named TMP102 board, supply/wiring/address, native driver and reference thermometer, conversion delay and loss checks. No sensor scan, claimed calibration/accuracy, TMP110/TMP113 inheritance or actuator operation. Missing/error/startup-not-ready returns unavailable, never zero temperature.

### SPI: `linux-mcp3008-iio-ch0-raw-read/1`

Select an already provisioned Microchip MCP3008 on one enrolled SPI controller/chip-select, using the existing Linux `mcp320x` IIO driver and single-ended channel 0. Read only `in_voltage0_raw`; preserve an integer code 0–1023 with unit `1`, channel and reference configuration provenance. Current driver source selects 10-bit MCP3008 conversion and `INDIO_DIRECT_MODE`; it does not establish buffered capture. The wire reference is Microchip DS20001295E (2022): start, single-ended selection, channel bits and ten result bits; freeze board SPI mode/clock/chip-select provisioning. [Microchip datasheet](https://ww1.microchip.com/downloads/aemDocuments/documents/MSLD/ProductDocuments/DataSheets/MCP3004-MCP3008-Data-Sheet-DS20001295.pdf), [kernel driver](https://github.com/torvalds/linux/blob/master/drivers/iio/adc/mcp320x.c).

No raw spidev access, device rebinding, differential channel, DAC/control write or on-demand bus setup. SPI lacks low-level transfer acknowledgement; a successful transfer or plausible code cannot identify a present ADC. [SPI API limitations](https://docs.kernel.org/spi/spidev.html). First software check: exact sysfs numeric fixtures, bounds, errors, identity change and held native-read cancellation/settlement. Equipment: named board/ADC, safe voltage reference/input source, mode/timing validation and disconnected-input behavior. Native driver absence or unknown layout is unsupported. Raw code is not voltage or a calibrated physical reading.

### NFC/RFID: `linux-pcsc-reader-presence/1`

Use PC/SC through pcsc-lite API documentation version 2.4.1, one enrolled contactless-capable reader/driver. `SCardEstablishContext`, `SCardListReaders`, bounded `SCardGetStatusChange`, `SCardCancel` on the same context, and `SCardReleaseContext` delimit observation. Preserve reader-state bits (present/empty/unknown/unavailable/mute/in-use/exclusive) rather than coercing every failure to absent. Reader names are not stable identity proof. [Official API](https://pcsclite.apdu.fr/api/group__API.html).

Permit presence events only. No `SCardConnect`/APDU exchange, reader-control command, UID extraction, authentication assertion, tag writes or payment/access credential reading. NFC/RFID frequency, card technology and firmware supported by the actual reader must be enrolled; this is not LF/UHF/universal tag support. First software check: producer-shaped state bitmask and return-code fixtures, cancelled/timeout wait, daemon/reader loss, duplicate states and exact context release. Equipment: named reader, contactless driver/firmware and owner-approved test cards, insertion/removal/loss and OS permission checks. pcsc-lite reports API differences from Windows; macOS uses Apple's implementation, so neither inherits this Linux profile. Main code uses a BSD-like license with some files under other licenses; pin the installed package/driver and inspect its actual notices before packaging. [Project/platform/license notes](https://pcsclite.apdu.fr/).

### Legacy RF: `rtl2832-receive-iq-capture/1`

Select one enrolled RTL2832-based receiver supported by a pinned Osmocom librtlsdr artifact, receiver serial/USB identity, exact tune frequency, sample rate and gain settings. The first resource is bounded native interleaved unsigned-byte I/Q capture, with capture configuration, receiver arrival clock, dropped/short-read status and exact byte length. It is a receiver profile, not an inferred legacy appliance decoder. The official recorder calls buffer reset before capture; `rtlsdr_read_async` has explicit buffer count/length and blocks until cancellation. Freeze the actual library version/build; mutable master is research evidence only. [Official recorder](https://github.com/osmocom/rtl-sdr/blob/master/src/rtl_sdr.c), [native API](https://github.com/osmocom/rtl-sdr/blob/master/include/rtl-sdr.h).

Permit receiver configuration and capture only, on equipment/frequencies the owner has authorized for reception. Exclude transmission, bias-tee changes, direct sampling, remote rtl_tcp service, kernel-driver detachment and protocol replay. Native buffers cannot be mapped wholesale into the 128-member signal-array schema; use a future explicitly bounded verified capture resource, or report the profile unsupported pending its public caller contract. First software check: documented byte fixture, odd/truncated pair rejection, buffer/total-byte quota, callback after cancel, asynchronous native join and actual release. Equipment: named dongle/tuner/driver, approved signal source and reception setting; loss/overload and bounded stop evidence. No state, packet identity, units or transmitter authenticity is derived from raw I/Q. Osmocom distributes GPL-licensed code; process/library distribution and libusb dependencies need exact license review before choosing packaging. [Official license](https://github.com/osmocom/rtl-sdr/blob/master/COPYING). A named proprietary RF decoder remains a separate unresolved target choice; it is not needed to record this receive-only candidate.

### HDMI-CEC: `linux-cec-no-initiator-monitor/1`

Use the Linux CEC userspace API on one enrolled `/dev/cecX` adapter. `CEC_S_MODE` selects `CEC_MODE_NO_INITIATOR | CEC_MODE_MONITOR`; this observes the adapter's own received/transmitted messages, not every directed frame on the bus. It requires `CAP_NET_ADMIN`; absent capability is denial, never automatic elevation. MONITOR_ALL requires an additional advertised hardware capability and is excluded. [Mode contract](https://docs.kernel.org/userspace-api/media/cec/cec-ioc-g-mode.html).

Receive `cec_msg` frames with length at most 16, native rx status and timestamp; preserve initiator/destination/opcode bytes as protocol data. A receive success does not establish TV state or physical command effect. [Receive ABI](https://docs.kernel.org/userspace-api/media/cec/cec-ioc-receive.html). Exclude transmit, logical-address acquisition, power/standby/input commands and remote-key injection. The adapter may already have kernel CEC processing enabled by its host; enrollment must document that separate behavior. First software check: native message/status fixtures, unknown opcodes, malformed length, timeout/EAGAIN, disconnect and exact descriptor closure. Equipment: CEC-capable adapter/kernel and owner-approved display/source topology, hotplug and capability/permission tests. No HDMI video capture, HDCP access or full HDMI/CEC semantic compliance claim. A future command profile would require its precise CEC specification/license and effect qualification separately.

### Building automation: `bacnet-ip-selected-ai-read/1`

Choose BACnet/IPv4 unicast, one explicitly enrolled device address/port and Device instance, one AnalogInput instance, and read-only `ReadProperty` of Present_Value, Units, Status_Flags and Out_Of_Service. The normative reference is ANSI/ASHRAE 135-2024 with applicable errata/addenda; current committee information records Protocol_Revision 31. Freeze the target's actual advertised revision, PICS and native implementation; do not infer revision from the latest standard. The smallest initial producer can be the BACnet-stack maintainer's local AnalogInput object, with the exact selected source/build pinned. It demonstrates software wire behavior only. [Standard access](https://bacnet.org/buy/), [revision information](https://bacnet.org/updates/), [maintainer object](https://github.com/bacnet-stack/bacnet-stack/blob/master/src/bacnet/basic/object/ai.c).

Present_Value is a BACnet REAL; Units is an enumeration and Status_Flags a four-bit string. Keep all native flags. Fault/out-of-service data is diagnostic and cannot be silently advertised as a valid physical measurement; unmapped units remain unsupported, and separate reads are not an atomic snapshot. Bind invoke ID, peer, object/property, operation epoch and original timeout before accepting an ACK; reject unknown/mismatched types, segmented replies for this first nonsegmented profile, Reject/Abort/Error and unsolicited traffic. Exclude Who-Is broadcast, BBMD/foreign-device registration, routing, COV subscription, writes and BACnet/SC inheritance. Ordinary BACnet/IP does not provide authenticated device identity; record gateway/owner enrollment limitations and use only the selected authorized local/isolated network scope.

First software check: producer-generated wire fixture plus loopback selected server, actual ACK/error/abort/timeout, wrong peer/object/invoke, nonfinite REAL, flag suppression, units and partial tuple failure. No server/dependency is installed by this research. Equipment: named controller/firmware/PICS and one safely observed AnalogInput, actual units/reference and fault/loss tests. ASHRAE offers a free read-only preview and purchased standard; the full clauses were not retrieved by this text research. Exact clause verification is required before implementation/conformance claims. BACnet-stack's source licenses vary (GPL with exception, MIT/Apache examples); file-level license/dependency review is required before adopting it, not a new approved dependency here. [Maintainer licensing/version notes](https://github.com/bacnet-stack/bacnet-stack/blob/master/README.md?plain=1).

### Low-power radio: `chirpstack-v4-selected-uplink-mqtt/1`

Use an owner-controlled ChirpStack v4 installation already commissioned for one LoRaWAN 1.0.4 Class A test device and exact region settings. The adapter boundary is its MQTT integration, not a new LoRa radio stack: enroll broker identity/ACL and the exact `application/<applicationId>/device/<devEui>/event/up` topic, with no wildcards. The producer uses Protobuf JSON mapping; decode bounded UplinkEvent fields, opaque base64 data, fPort/fCnt, deduplicationId and selected rx metadata against the pinned integration.proto. Missing proto3 defaults and optional metadata need faithful producer fixtures, not invented mandatory fields. [MQTT integration](https://www.chirpstack.io/docs/chirpstack/integrations/mqtt.html), [event format](https://www.chirpstack.io/docs/chirpstack/integrations/events.html), [exact message definition](https://github.com/chirpstack/chirpstack/blob/master/api/proto/integration/integration.proto).

Preserve server-reported UTC/IDs/radio metadata in provenance and opaque bytes as a bounded resource; no payload codec or measurement units are implied. A topic/DevEUI is not proof of MIC verification by this adapter. Join/session changes, duplicates, stale/retained replay and fCnt reset/wrap must not be interpreted as fresh application measurements. No join commissioning/key extraction, gateway registration, downlink enqueue, command topic or remote server creation. Reuse selected MQTT quota/authority/epoch handling only after verifying the exact broker/producer QoS, retained policy and content-type behavior; do not copy A11-specific MQTT5/content-type assumptions into ChirpStack.

First software check: official producer-shaped JSON/protobuf fixtures for identity, base64, defaults, duplicate keys, size/UTF-8, deduplication, counter/session change and retained/stale refusal; then an owner-controlled local broker software caller. Equipment: named commissioned node/gateway/region/server build, actual uplink/loss/rejoin and permission results. The public LoRaWAN 1.0.4 specification is available; its certification tool is member-only. Certification and regional RF settings are equipment qualification gates, not research blockers. [LoRaWAN package/access boundary](https://lora-alliance.org/resource_hub/lorawan-104-specification-package/).

### Analog capture: `mcp3008-ch0-low-rate-code-capture/1`

Reuse the selected MCP3008/IIO direct-read path above as the first analog capture candidate: one single-ended channel, explicit low-rate polling ceiling, bounded code values, read completion/arrival time and unknown sensor capture time. The kernel driver's scale uses its configured regulator reference and 10-bit resolution; configured scale is not independently measured calibration. Freeze that nominal reference metadata, preserve raw code, and gate any volts output behind an explicit unit conversion/calibration profile with measured reference and front-end provenance. Current direct-mode driver evidence forbids a claim of buffered sampling, uniform intervals or lossless high-rate waveform capture. [Kernel conversion/scale/direct-mode source](https://github.com/torvalds/linux/blob/master/drivers/iio/adc/mcp320x.c).

First software check: raw code, nominal scale and unavailable calibration fixtures, actual bounded consumer, irregular polling/late read, channel/reference identity change and cancellation. Equipment: ADC board plus reference voltage and safe calibrated signal source; reference drift, input range, disconnected/floating input, saturation, conversion error and sample timing measured. Raw full-scale is a code, not automatically a quality flag; clipping/overrange must have actual evidence. Arbitrary analog audio/video, higher-rate IIO buffers and other channels remain separate choices. Linux IIO buffer metadata defines endian/sign/valid bits/storage bits/repeat/shift and scan order; if a later driver supports buffering, all those exact settings must be enrolled and tested instead of assuming this driver's layout. [IIO buffer contract](https://docs.kernel.org/driver-api/iio/buffers.html).

## Common future software gate and research decision

`profiles.json` records proposed numerical software bounds for these research profiles. They are initial plan budgets, not measured throughput or hardware safety qualification. Every acquisition/read retains the caller's original deadline; a native poll timeout does not grant a new deadline. In particular, the finite RF capture's five-second observation window is distinct from a one-second maximum native poll wait. Hardware loss or native teardown can remain uncertain after either timeout.

For every profile: immutable enrollment; genuine cancellation signals; exact approval before native dispatch; bounded parser/state/bytes/work/timers; original operation deadlines; no queued replay after reopen; epoch-bound callbacks; native acquisition/open/close settlement retained through cancellation; observer failure isolated; no failure converted to a successful sample. Denial, busy, unsupported format/API, unavailable device, stale/lost source and uncertain native teardown are distinct outcomes. No reconnect starts physical capture or resumes a grant without current authority. Physical evidence must retain exact kernel/library/firmware, permissions, bounds, clocks, measured calibration where claimed and actual raw-handle release.

Faithful software fixtures must exercise GPIO sequence wrap/loss, PC/SC timeout as no-change rather than absent, BACnet's four-read tuple against one unchanged original deadline, and byte-stream quotas without implicit array-schema widening. The first protocol fixture is produced by its actual selected native producer/software backend; manually invented “plausible” device output is insufficient. Native libraries are host implementation options awaiting artifact/license review, not dependencies approved or introduced by this research record.

These are permitted research candidates subject to the stated native/resource authority, not an owner authorization to access any live device. Research acceptance can be met locally by recording this scope and these sources. Outstanding pre-implementation decisions are exact native build/packaging, BACnet normative clauses/PICS and target identity, proprietary legacy RF decoder if desired, and actual LoRa producer settings/session identification. Equipment selection and physical receipts belong to future qualification. There is no unresolved requirement to obtain hardware merely to finish A15's research record, and no dependency has been added or support status changed.

This is the accepted A15 research contract record. It creates no qualified support row. Each subsequently implemented profile gets its own bounded plan, artifact pins, public installed caller and physical qualification row. Preserve A16 and Q03/Q08 as open until their actual required evidence exists.
