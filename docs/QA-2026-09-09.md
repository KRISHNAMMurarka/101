# Local QA — 9 September 2026

Environment: Apple M3 Max, 128 GiB RAM, Node 24.14.0, Codex in-app browser. Browser work used the local development server on localhost:3101. No external preview, deployment, push, or remote test service was used. The production build and server-render tests run separately.

## Route and layout evidence

Inspected 31 routes at 320×740, 740×320 and 2560×1440 in both themes: **186 DOM/keyboard-entry smoke checks**. Routes were the launcher, devices, controller, Studio and its seven tools, and the chooser/play pair for Slashstorm, TiltDrift, BodyDodge, Orbital Crew, BeatForge, GravityStack, Spellcaster, Echo Maze, Shadow Arena and Swarm Commander. Catalog bench used 50 entries.

Checks recorded document width, horizontal overflow, heading, computed theme background, and focus after Tab. The lazy InputLab initially had no heading during loading; a subsequent accessibility-tree and screenshot check confirmed its complete interface and focusable canvas. GravityStack similarly creates its canvas after initialization. These checks do not prove every gameplay action or a complete keyboard journey.

The matrix found VisionLab at 363px on a 320px viewport. Its diagram columns had intrinsic minimum widths; after the batch, columns were corrected and a 320px recheck showed scrollWidth=320. All other matrix cases had no document overflow. Earlier exploratory checks found launcher scrollWidth=353 at 320px; corrected grid minimums and retested at 320px before the matrix.

Representative screenshots were inspected for the launcher, result overlay, controller stress layouts, VisionLab, InputLab, and controller dock. This is a bounded layout review, not a claim of a pixel-by-pixel visual audit of every state.

## Interaction evidence

- A completed Slashstorm run originally left focus on CANVAS. The shared result panel now focuses the Play again button and associates the score with it. BodyDodge also showed the focused restart control.
- Light mode originally rendered the score in rgb(10,10,10) against a dark scrim. After correction, result text is rgb(242,242,242) and secondary text rgb(188,188,188). Dark canvas overlays now own their text palette independently from the page theme. Contract tests verify text/control contrast for both page themes and result scrims.
- An eight-button controller layout clipped/wrapped long labels outside their buttons at 320px. Container-relative labels and bounded wrapping corrected it; measured label overflow became zero. Center-only and two-left-pad layouts are covered by planner tests; two-pad browser layout remained within 320px.
- BodyDodge's dock opens below the canvas and feeds the existing host. At 740×320 fullscreen, measured canvas ended at y=122 and dock began at y=123: reserved space, no canvas overlap. The dock uses 197px here, leaving a small game field; physical landscape playability needs review. A subsequent completed run confirmed controls collapsed (aria-expanded=false), canvas height recovered to 265px, and focus moved to Play again. Portrait dock buttons measured 44–64px high; d-pad cells about 52.7px. Fullscreen target increased to 44px.
- An invalid pairing code previously showed raw ticket vocabulary and a Connected disclosure while the session said WAITING. It now says Connect to a game and gives a short scan/paste recovery instruction.

## Camera and performance evidence

The chooser enumerated a built-in camera and a phone continuity camera. The built-in camera started successfully. Use this camera advanced to placement; actual inference produced “We can only see part of you” and corrective instructions. Tab/Return advanced to Check, and keyboard Skip returned to the chooser. Heading focus now follows each setup beat and returns to the chooser on cancellation. Navigation stops the owned adapter; no recording is enabled.

VisionLab showed active real pose inference at **10.9 ms** in one unthrottled snapshot and **16.4 ms** in one snapshot with CDP CPU throttling set to 4×. These are individual observations on the M3 Max, using the bundled lite model, not mean/p95 measurements, end-to-end frame latency, a phone benchmark, or proof of complete placement/gesture confirmation. GPU work is not proportionally slowed by CPU emulation. CPU throttling was reset to 1× afterward.

Physical final gestures, the eight-second alternate step, person crossings, unplug/permission-denial recovery, selected-camera persistence through a real completed walkthrough, and complete play with/without camera have not been certified. Fake-stream/backend integration tests exercise the actual adapter/bus/game path but cannot establish physical accuracy. See VISION-VALIDATION.md for fixture/producer review.

## Production and automated checks

The prior built stylesheet referenced /_next/static/fonts/*.woff2 while files existed only under /fonts. The emitted-font test was observed failing with ENOENT before the fix. Fonts now enter Vite as source-managed assets. The offline stamper also had to recognize Controller as a shared chunk after the game dock began importing it.

The offline controller package includes a hashed HTML shell and 31 dependent assets, including four fonts. Atomic install failures preserve the prior version; no forced takeover interrupts its clients. Tests execute worker handlers against a mock CacheStorage and fetch implementation, including a version transition.

The production controller was also checked in a local browser at `localhost:3102`: `/sw.js` registered with `/controller` scope, took control after one reload, and then loaded `/controller?session=OFFLINE99` with browser networking disabled. It displayed `OFFLINE99`, rather than the cached shell's `101LAB` room, and its controller controls remained available. Browser networking was restored immediately after the check. This proves a current-build offline reopen and URL hydration path. It does not prove an installed-device upgrade between two different production builds.

A cross-build controller lifecycle was then exercised in a fresh local browser origin at `localhost:3103`. Build A from `5d9e35a` installed cache `101-link-15a8dc66c0b6c53f`; build B from the source of `b1953d5` installed `101-link-6664efd0a6b493b9` while the A client remained active. The newer worker waited rather than taking control. With browser networking disabled, the active A client reloaded to `BUILD-A` and retained usable controls. After every A-controlled page closed, B activated, removed the obsolete A cache, and reopened offline at `BUILD-B-OFFLINE` with the requested room and controls. Networking was restored and the temporary browser closed. This is real desktop-browser service-worker evidence; it does not replace an installed-PWA check on a physical device.

The offline hydration review also found that a cached shell could retain session101LAB from its server props. The controller now waits for the current URL snapshot before creating a transport, preserving valid case/hyphens and clearing absent cached pairing data. Five regressions cover that route boundary.
